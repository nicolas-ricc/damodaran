# Static analysis viewer (#92) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bot site` pre-renders a read-only htmx site listing every company analysed by `bot analyze` and showing, without prose, why each got its margin-of-safety verdict; every push to `master` builds it from committed JSON and deploys it to GitHub Pages.

**Architecture:** `bot analyze` writes a `<TICKER>.json` sidecar next to the `.md/.html` reports; only the sidecars are committed. A new package `src/bot/web/` holds three pure modules (`index` scans the sidecars, `views` turns one JSON dict into typed view-models, `svg` draws the hand-drawn charts) and one edge module (`site` renders Jinja2 templates into files). A GitHub Actions workflow gates on lint/types/tests, runs `bot site`, and deploys to Pages.

**Tech Stack:** Python 3.12, Jinja2 + markupsafe (already installed), htmx 2.x vendored, structlog, typer, pytest, ruff, mypy --strict, GitHub Actions + Pages.

**Spec:** issue #92 (acceptance criteria are binding) + `docs/superpowers/specs/2026-10-04-web-viewer-design.md` (Spanish; layout, notation, visual direction). Earlier draft plan: `docs/superpowers/plans/2026-10-04-web-viewer.md` (this plan supersedes it; same 9-task shape, made concrete). Visual contract: `.impeccable/surfaces/src-bot-web-templates-base-html.md` + `docs/DESIGN.md`.

## Global Constraints

- Read-only: the site never writes outside `--out` and never invokes the pipeline, DuckDB or any network service.
- No new runtime dependencies. No server, no FastAPI, no CDN. htmx 2.x vendored.
- `bot site` must work with **no env vars set**: it must not call `load_settings()` or `_open_db()`.
- Verdict is MoS only: `>=1.3` undervalued, `>=1.0` fair, `<1.0` overvalued, no price → `n/a`. One shared function `margin_verdict` in `reporting/analysis_report.py`.
- UI copy is English, labels only: no CTAs, no explanatory text, no search, no "Full report" link, no tooltips with prose. Only long text allowed: the bot's own `reason` strings (story reasons, flag reasons).
- Colour never encodes alone: every verdict/flag mark is pigment + shape.
- Wobble SVG filters only on detail-view groups; never on list rows, never on text.
- Every `href`/`hx-get`/`hx-push-url` starts with `base_url`.
- Tickers must match `^[A-Z0-9.\-]{1,12}$` before reaching a file name; date folders must parse as ISO dates. Jinja autoescape on.
- Fonts from `docs/plano/fonts/*.b64` decoded to woff2, with OFL license files shipped. Literata italic is not shipped (anti-goal: editorial italic).
- Tests live in `tests/unit/test_web_*.py` (the repo's flat `tests/unit/` convention, not `tests/web/`).
- `uv run ruff check . && uv run mypy src && uv run pytest -q` green after every task. Baseline at 939da6f: 922 passed, 1 skipped.
- Commits: Conventional Commits with the issue scope, e.g. `feat(#92): ...`.

## Review Focus

1. `bot site --out .` (or any existing non-site directory) must not wipe it: `build` empties `out_dir` only if it is absent, empty, or carries the `.bot-site` marker a previous build wrote; otherwise it raises `ValueError` and the CLI exits 2. Test in Task 6.
2. A negative intrinsic value (DCF equity below zero) or a negative MoS must render: verdict `overvalued`, value line axis extends below zero, no crash. Test in Tasks 3 and 4.
3. `--base-url` given as `/damodaran` or `damodaran/` or `` must normalise to `/damodaran/` / `/`. Test in Task 6.
4. A company name or reason containing `&`, `<` or quotes (`AT&T <Inc>`) is escaped, never injected. Test in Task 6.
5. An analysis whose tornado has every `intrinsic_low/high` = `None` still gets a value line (range collapses to the intrinsic) and an empty drivers section. Test in Task 3.

**Files:**

```python
class Verdict(StrEnum):
    UNDERVALUED = "undervalued"; FAIR = "fair"; OVERVALUED = "overvalued"; NA = "na"

VERDICT_TEXT: dict[Verdict, str]   # Verdict -> margin_verdict wording ("potentially undervalued", ...)
FILTER_LABEL: dict[str, str]       # {"all": "all", "undervalued": "undervalued", "fair": "fair", "overvalued": "overvalued", "na": "n/a"}
FILTERS = ("all", "undervalued", "fair", "overvalued", "na")
SORTS = ("ticker", "mos", "date")
DIRECTIONS = ("asc", "desc")

def verdict_of(margin_of_safety: float | None) -> Verdict   # via margin_verdict, never re-implementing thresholds
def verdict_from_text(text: str) -> Verdict                 # inverse of VERDICT_TEXT; unknown text -> NA

@dataclass(frozen=True)
class ValueLine:
    price: float; intrinsic: float; range_low: float; range_high: float
    axis_min: float; axis_max: float; verdict: Verdict
    @property
    def fair(self) -> float: return self.price          # 1.0x threshold
    @property
    def undervalued(self) -> float: return self.price * 1.3  # 1.3x threshold

@dataclass(frozen=True)
class RowView:
    ticker: str; name: str; verdict: Verdict; mos: float | None
    price: str; intrinsic: str        # formatted with fmt_per_share
    story: str                        # story_type or "—"
    flags: tuple[str, ...]            # colours of red/yellow flags only, in flag order
    date: date; value_line: ValueLine | None

@dataclass(frozen=True)
class ScenarioGrid:
    axis_a: str; axis_b: str                 # fmt_axis_label(SensitivityAxis(...))
    row_labels: tuple[str, ...]; col_labels: tuple[str, ...]  # fmt_mult
    cells: tuple[tuple[Verdict | None, ...], ...]   # None where the cell's MoS is None
    matching: int; total: int                # cells equal to the base verdict / non-None cells

@dataclass(frozen=True)
class TornadoBar:
    label: str; low: float; high: float      # intrinsic_low/high, both non-None

@dataclass(frozen=True)
class LabelledValue:
    label: str; value: str; source: str      # source "" when not applicable

@dataclass(frozen=True)
class FlagView:
    name: str; color: str; reason: str

@dataclass(frozen=True)
class DetailView:
    ticker: str; name: str; date: date; story: str; story_reasons: tuple[str, ...]
    verdict: Verdict; verdict_text: str; mos: str      # fmt_ratio, "n/a" when None
    price: float | None; intrinsic: float
    value_line: ValueLine | None; grid: ScenarioGrid | None
    tornado: tuple[TornadoBar, ...]; assumptions: tuple[LabelledValue, ...]
    flags: tuple[FlagView, ...]; sanity: tuple[LabelledValue, ...]   # value = "implied / sector"
    dcf_rows: tuple[tuple[str, ...], ...]    # year, revenue, EBIT, FCFF, PV (fmt_money)
    dcf_totals: tuple[LabelledValue, ...]    # Enterprise value, Net debt, Equity value
    history: tuple[date, ...]                # newest first, all dates of this ticker

def row_view(ref: AnalysisRef) -> RowView
def value_line(analysis: Mapping[str, Any]) -> ValueLine | None
def scenario_grid(analysis: Mapping[str, Any]) -> ScenarioGrid | None
def detail_view(entry: CompanyEntry, ref: AnalysisRef) -> DetailView
def filter_sort(rows: Sequence[RowView], verdict: str, sort: str, direction: str) -> list[RowView]
```

Rules (decided here):
- The verdict shown everywhere is `verdict_from_text(data["verdict"])`, i.e. what `bot analyze` stored, so web and `.md` never disagree. Grid cells use `verdict_of(cell["margin_of_safety"])`.
- `value_line`: `None` when `current_price` is `None` or `<= 0`. `range_low/high` = min/max of `{intrinsic} ∪` every non-`None` `intrinsic_low`/`intrinsic_high` in `tornado`. `axis_min/max` = min/max of `{price, price*1.3, range_low, range_high}` padded by 5% of the span on each side (span 0 → pad 1.0).
- `scenario_grid`: `None` when there is no price (`grid.reference_price` is `None`); `total` counts non-`None` cells; `matching` counts cells equal to the row's stored verdict.
- Assumptions table rows and formatters copy `src/bot/reporting/templates/analysis.md.j2` lines 32-41 (same labels, same formatter per row; revenue growth shows year 1 as `fmt_pct(value[0])`, `—` if value is `None`). Source is the enum value string.
- Sanity: `P/E` → `f"{fmt_num(implied_pe)} / {fmt_num(sector_pe)}"`, `EV/Sales` likewise.
- `filter_sort`: filter `all` keeps everything, otherwise `row.verdict.value == verdict`. Sort keys: ticker (str), mos, date. Rows whose `mos` is `None` always go last regardless of direction; ties broken by ticker ascending. Unknown argument → `ValueError`.

### Task 4: `web/svg.py` — hand-drawn charts

**Files:**
- Create: `src/bot/web/svg.py`
- Test: `tests/unit/test_web_svg.py`

**Interfaces:**
- Consumes: `ValueLine`, `ScenarioGrid`, `TornadoBar`, `Verdict` (Task 3).
- Produces (all return `markupsafe.Markup`):

```python
def seed_of(key: str) -> int          # zlib.crc32(key.encode()); never hash() (randomised per process)
def jitter_path(points: Sequence[tuple[float, float]], seed: int, amp: float = 0.6) -> str  # SVG "d" string
def value_line_svg(vl: ValueLine, *, mini: bool, seed: int) -> Markup
def scenario_grid_svg(grid: ScenarioGrid, *, seed: int) -> Markup
def tornado_svg(bars: Sequence[TornadoBar], *, price: float | None, seed: int) -> Markup
def verdict_mark(v: Verdict) -> Markup
def flag_mark(color: str) -> Markup   # "red" | "yellow" | "green" | "unknown"
```

Rules:
- `jitter_path`: subdivide each segment into ~8px steps, offset each interior point perpendicular by `random.Random(seed).uniform(-amp, amp)`; endpoints fixed; coordinates rounded to 1 decimal. Same inputs → same string.
- Colours only through CSS custom properties, using `docs/plano/part-head.html` names: `var(--ink)`, `var(--ink-soft)`, `var(--p-selecciona)` (olive, undervalued), `var(--p-datos)` (ochre, fair), `var(--p-elimina)` (terracotta, overvalued), `var(--p-valua)` (indigo, intrinsic). No hex/rgb/oklch literals in `svg.py`.
- Value line (`mini=False`, viewBox 640×96): jittered axis; olive-shaded zone from `vl.undervalued` to `axis_max`; translucent indigo range band `range_low..range_high`; tick marks at `vl.fair` (1.0×) and `vl.undervalued` (1.3×); price = vertical bistre stroke; intrinsic = indigo circle; the price→intrinsic segment stroked in the verdict pigment. Each drawn group wrapped in `<g filter="url(#wobble-N)">` (N 1–4, chosen from `seed`); tick labels `1.0×`, `1.3×`, and the price/intrinsic numbers are `<text>` **outside** filtered groups. `mini=True` (viewBox 120×16): same geometry, jittered paths only, no `<text>`, no `filter=`.
- `scenario_grid_svg`: 5×5 cells; a cell's fill is the verdict pigment **plus** its verdict shape drawn small inside (check / open circle / hatch via `url(#hatch)` / dash); `None` cell = dotted empty outline. Rows/cols labels as `<text>` outside the filtered group.
- `tornado_svg`: one horizontal bar per entry (widest first, input order), from `low` to `high` on a shared axis, with a bistre price tick when `price` is not `None`; labels outside filtered group.
- `verdict_mark` shapes: undervalued = double-stroke check (olive); fair = open circle (ochre); overvalued = gate with diagonal hatching (terracotta, `url(#hatch)`); na = dash (`--ink-soft`). `flag_mark`: red = hatched gate (terracotta), yellow = open circle (ochre), green = check (olive), unknown = dotted empty outline (`--ink-soft`). Every mark has `role="img"` and a `<title>` (the verdict/flag word) and is 16×16 with no filter.
- `#hatch` pattern and `wobble-1..4` filters are defined once in `base.html` (Task 5), never here.
