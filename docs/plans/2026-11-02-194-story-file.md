# Story file (`founded_year`, `story`, `scenarios`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The override YAML `config/assumptions/<TICKER>.yaml` accepts the hypergrowth story file (`founded_year`, `story`, `scenarios`). A new pure module parses and validates it into a frozen dataclass. Every error is a per-ticker `ValueError` that never stops a `bot analyze` batch.

**Architecture:** The new pure module `src/bot/valuator/hypergrowth.py` owns the story schema: `StoryInputs`, `parse_story`, `parse_scenarios` and `story_from_override`. `src/bot/valuator/assumptions.py` keeps the single override gate. It renames `_load_override` to the public `load_override`, adds the three keys and the rules that span keys, and calls `story_from_override` so a malformed story fails when the file is loaded. Nothing consumes the story yet; `AssumptionSource.STORY` is added and is not emitted yet.

**Tech Stack:** Python 3.12, PyYAML, pytest, Typer `CliRunner`, mypy strict, ruff.

**Spec:** GitHub issue #194 (sub-issue of #192; read both). Context: spec §7.6 in `docs/superpowers/specs/2026-05-25-investment-bot-design.md`, plan #180 `docs/plans/2026-10-31-180-override-errors-per-ticker.md`.

## Global Constraints

- Modules under `src/bot/valuator/` are pure: no I/O, no global state, frozen dataclasses. Every module constant has a `#:` comment that explains its value.
- Story file units are those of `financials_annual`: raw reporting currency, not millions.
- Every error is a `ValueError` whose message starts with `where` (the file path) and names the key.
- Existing override files without the new keys load exactly as before. Every test in `tests/unit/test_valuator_assumptions.py` passes with only the rename (plus the enum-membership set, which must list `story`).
- Isolation: no story type changes behaviour. Nothing reads `StoryInputs` in this issue.
- Green: `uv run pytest -q`, `uv run ruff check . && uv run mypy src`, `python3 docs/leccion/check.py`.
- Commits: Conventional Commits with `#194`.

## Decisions (technical assumptions)

1. `StoryInputs` is `@dataclass(frozen=True, kw_only=True)` with fields in the issue's schema order. `kw_only` lets the required fields keep the schema order alongside the defaulted ones.
2. Numbers follow the existing override rule (`assumptions._is_finite_number`): an `int`/`float` (never a `bool`) or a `str` that `float()` parses, and finite. The reason is that PyYAML reads `1e11` (no dot) as a string. The helper moves to `hypergrowth.py` as public `is_finite_number`, and `assumptions.py` imports it from there. That leaves one copy, and no circular import because `hypergrowth` does not import `assumptions`. Values are stored as `float`.
3. Integers (`margin_converge_year`, top-level `founded_year`) must be an `int` and not a `bool`. `5.0`, `"5"` and `2.5` are refused.
4. A story key given as `null` is refused like any non-number. An absent optional key takes its default (`None` for `wacc_terminal` and `terminal_roic`).
5. A scenario is validated key by key with the same per-key validators, then merged with `dataclasses.replace`. No rule spans fields, so this is the same as re-validating the merged result.
6. `scenarios: {}` (empty) and an empty single scenario (`worst: {}`) are both `ValueError`. Scenario names must be strings.
7. The story-type literal is `hypergrowth.STORY_TYPE = "hypergrowth"`. `StoryType.HYPERGROWTH` arrives in #195. Until then a valid story file still logs today's `assumptions.story_type.invalid` warning in `resolve_assumptions`, and no story-type branch runs.
8. `founded_year`, `story` and `scenarios` skip `_check_override_values`'s generic numeric check. They have their own rules, and the generic check stays untouched for every other key.
9. The two comments in `docs/pipeline/models/analyze.tla` that cite `_load_override` change to `load_override`. They are comments only, so TLC and the boards are unaffected.

## Assumptions (from plan grilling)

10. `story_from_override` follows the issue literally: it returns `None` when `story` is absent, even if `scenarios` is present. `load_override` is the gate that refuses `scenarios` without `story`. Rejected alternative: duplicating that rule in `story_from_override`.
11. Scenarios can only override story keys, never unset them back to `None`. The issue says a scenario is "a mapping of a subset of story keys, merged over `base` with `dataclasses.replace`". Rejected alternative: letting `null` mean "back to the default".
12. No rule spans fields (for example `wacc_terminal <= wacc_start`). The issue gives one range per key ("ranges as in the comments above"). Cross-field rules belong to the resolver (#196) if anyone ever needs them.
13. Units (raw reporting currency) are documentation only. A file written in millions by mistake cannot be told apart from a small company, so it loads.
14. Until #195 lands, a valid hypergrowth story file values the ticker non-branching, as any label outside `StoryType` does today (`tests/unit/test_valuator_assumptions.py::test_invalid_manual_story_type_warns_and_stays_non_branching`). Parent #192's plan gates the valuation in #195, so no test pins this transitional state.

## Review Focus

1. `target_revenue_y10: 1e12` written without a dot is read by YAML as a string, and must still load as 1e12. Test in Task 1.
2. A YAML `.nan` / `.inf` value, or a `"nan"` string, inside `story` must be refused and the key named. Test in Task 1.
3. `story:` with no value (YAML `null`) must be a `ValueError` saying the key must be a mapping, not a `TypeError`. Test in Task 2.
4. A scenario that sets a key to an out-of-range value (`worst: {target_margin: 1.2}`) must be refused and named as `scenarios.worst.target_margin`. Test in Task 1.
5. `founded_year: true` must be refused, because `bool` is an `int` subclass. Test in Task 2.

**Interfaces:**

  - `STORY_TYPE: str = "hypergrowth"`
  - `@dataclass(frozen=True, kw_only=True) class StoryInputs` with fields `year1_growth: float`, `target_revenue_y10: float`, `year1_margin: float`, `target_margin: float`, `margin_converge_year: int = 5`, `regulatory_drag: float = 0.0`, `sales_to_capital: float`, `wacc_start: float`, `wacc_terminal: float | None = None`, `effective_tax_rate: float = 0.0`, `terminal_roic: float | None = None`, `failure_probability: float = 0.0`, `failure_proceeds_pct_of_value: float = 0.0`, `fixed_commitments_pv: float = 0.0`, `extra_cash: float = 0.0`, `governance_discount: float = 0.0`.
  - `parse_story(raw: Mapping[str, Any], *, where: str) -> StoryInputs`
  - `parse_scenarios(raw: Mapping[str, Any], base: StoryInputs, *, where: str) -> dict[str, StoryInputs]`
  - `story_from_override(override: Mapping[str, Any], *, where: str) -> tuple[StoryInputs, dict[str, StoryInputs]] | None`. It returns `None` when `"story"` is absent, and `{}` scenarios when `"scenarios"` is absent.

Ranges (issue #194):

| key | rule | default |
|---|---|---|
| year1_growth | > -1 | required |
| target_revenue_y10 | > 0 | required |
| year1_margin | < 1 | required |
| target_margin | < 1 | required |
| margin_converge_year | int, 1..10 | 5 |
| regulatory_drag | 0..1 | 0 |
| sales_to_capital | > 0 | required |
| wacc_start | 0 < x < 1 | required |
| wacc_terminal | 0 < x < 1 | None |
| effective_tax_rate | 0..1 | 0 |
| terminal_roic | > 0 | None |
| failure_probability | 0..1 | 0 |
| failure_proceeds_pct_of_value | 0..1 | 0 |
| fixed_commitments_pv | >= 0 | 0 |
| extra_cash | >= 0 | 0 |
| governance_discount | 0 <= x < 1 | 0 |

Messages: `f"{where}: story.<key> must be <rule>, got {value!r}"`, `f"{where}: story is missing required key(s): a, b"`, `f"{where}: unknown story key(s): x. Valid keys: ..."`. Inside a scenario the prefix is `scenarios.<name>.` instead of `story.`.
