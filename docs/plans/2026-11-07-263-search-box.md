# Company search box — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (`.agents/skills/subagent-driven-development/SKILL.md`, per AGENTS.md) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The list pane of the site built by `bot site` gets a search box that narrows the visible rows by ticker or name as the reader types. It combines with the verdict filter (AND), survives htmx swaps, keeps `#count` and a no-match row in step, and stays invisible without JavaScript.

**Architecture:** There is no server-side search. One Jinja macro `search_box()` in `_controls.html` is rendered once in `list.html` (never in `rows_fragment.html`, so a `#rows` swap leaves it in place). The behaviour lives in the existing IIFE of `static/viewer.js`: `applySearch()` hides rows with the `hidden` attribute, rewrites `#count` and manages a `<tr id="search-empty">`, and the `htmx:afterSettle` handler for `#rows` re-applies it. `app.css` gains a single width rule.

**Tech Stack:** Jinja2 templates, plain CSS, vanilla ES5 JS (no build), pytest. Node is used only for `node --check` in one test.

**Spec:** issue #263 (child of story #257). Its "Decisions" and "Acceptance criteria" sections are binding. Background: `docs/superpowers/specs/2026-11-07-viewer-daisyui-search-design.md` §6 and §8.

## Global Constraints

- Markup, verbatim:
  ```html
  <label class="input input-sm" id="search" hidden>
    <span class="sr">Search by ticker or name</span>
    <input type="search" autocomplete="off" spellcheck="false" placeholder="Ticker or name" aria-controls="rows">
  </label>
  ```
- No-match row cell, verbatim: `<td colspan="9" class="none">No company matches "<span></span>". <button type="button" class="btn btn-link btn-xs">Clear search</button></td>`, inside `<tr id="search-empty">`, the last child of `#rows`. The query goes into the `<span>` through `textContent`, never `innerHTML`.
- `#count` text after a search: `visible + " of " + count.dataset.total`.
- `app.css`: `#search { width: 14rem; max-width: 100%; }`. No other styling. No literal colours (existing `test_css_reads_daisyui_variables_only`).
- Nothing is written to the URL, `localStorage` or `sessionStorage`.
- Filter and sort links keep `href` + `hx-get`, so the list still works with JavaScript disabled.
- Out of scope (other children of #257): the detail pane (#260), including `announceDetail`'s `.facts .lead-figure dd` selector; docs (#261); the impeccable passes and screenshots (#262).
- Commits use Conventional Commits with the `(#263)` scope. `uv run ruff check . && uv run mypy src && uv run pytest -q` green.

## Assumptions (declared, not in the issue's text; rejected alternative in brackets)

1. **The box is on every page that renders `list.html` with rows.** That covers `index.html`, `l/*.html` and `c/*.html` (`c/` pages extend `list.html` with `page_class="page-detail"`, `src/bot/web/templates/list.html:1-4`). Each has exactly one `id="search"`. Under 1100px a `c/` page shows only the detail (`body.page-detail`), so the hidden list pane carries the box along with it. [Rejected: index only. The issue says "Rendered in `list.html`", and `test_ids_are_unique_per_page` already runs over `c/AAA.html` and `l/all-ticker-asc.html`.]
2. **The server's no-rows row and the no-match row can both show.** With a non-empty query and a verdict filter that has no companies, `visible === 0`, so the no-match row is appended under "No company is fair yet." Both sentences are true. This is the issue's literal condition ("when `q` is non-empty and `visible === 0`"). [Rejected: suppress the no-match row when there are no company rows. That contradicts the literal rule, and the spec says the server row "is left alone", not that it replaces ours.]
3. **The no-match row is built from a constant string.** `tr.innerHTML = '<td colspan="9" …>…</td>'` (the constant above, no concatenation), then `tr.querySelector("span").textContent = raw`. The query never reaches `innerHTML`. [Rejected: `createElement` for every node. It is longer and cannot be pinned by one static string assertion.]
4. **`applySearch()` is a no-op without the box.** It returns when `input` is `null` (the empty site has no box and no rows). The `input`/`keydown` listeners are attached only when `input` exists.
5. **The query in the no-match row is trimmed, not lower-cased.** The issue says "the raw (trimmed) query", so it is `input.value.trim()`.
6. **Static assertions pin the behaviour.** There is no JS test runner (issue: "behaviour is pinned by static assertions on the script plus a `node --check` syntax test"). The `htmx:afterSettle` assertion slices the script from `"htmx:afterSettle"` to the end and checks that `applySearch()` appears before `restoreFocus()` there.

## Review Focus

1. **Search survives a filter or sort swap.** The new `tbody#rows` arrives unfiltered and the OOB `#count` reads `N of total`. `applySearch()` must run in the `afterSettle` branch for `rows`, before `restoreFocus()`. Pinned in Task 2 (order assertion).
2. **A query with markup characters** (`<img onerror=…>`, `"`) is shown as text in the no-match row. Pinned in Task 2: the constant cell string is present and the span is filled through `.textContent`.
3. **The selected company hidden by the search.** `markSelected()` must skip hidden rows (`if (row.hidden) return;`) and run again at the end of `applySearch()`, so the highlight comes back when the row reappears. Pinned in Task 2.
4. **Without JavaScript the box is invisible and the links navigate.** The label carries `hidden` in the static HTML, `app.css` keeps `[hidden] { display: none !important; }`, and every filter and sort link keeps `href` + `hx-get`. Pinned in Task 1.
5. **The box never travels in a fragment.** Any `rows/*.html` carrying `id="search"` would duplicate the box (and the query) on every swap. Pinned in Task 1 over all 30 fragments, plus the empty site.
