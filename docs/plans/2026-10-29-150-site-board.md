# Site board and consistency pass (#150) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw `docs/pipeline/site.d2` (publish → CI → `bot site` → GitHub Pages), link it from `pipeline.d2`, and close story #144 with a consistency pass over all six boards: `CONTEXT.md` vocabulary, ADR status words, every discrepancy with `docs/plano/part-data.js` and `docs/leccion/index.html` drawn as a `gap` note, a four-questions audit of every `step`, the final README, and a green CI render.

**Architecture:** One new board pulling `...@classes`, in four containers (`publish`, `ci`, `build`, `serve`) plus top-level files and outputs. Every other change is an edit to an existing board. Tests in `tests/unit/test_pipeline_diagram.py` (written in stage 3, before any board edit) pin the site board's nodes, phrases and citations, and add four board-wide tests: vocabulary, ADR status, step audit, document gaps. Two tests read the committed SVGs (labels shown, links resolve), so they only pass after the CI render is committed. Rendering happens only in the `pipeline-diagram` workflow (no d2 locally).

**Tech Stack:** d2 v0.9.0 + TALA (CI only), Python 3 / pytest, `docs/pipeline/check.py` (stdlib).

**Spec:** GitHub issue #150 (child of story #144), its "Inherited decisions" section, and `docs/pipeline/README.md` (directive syntax).

## Global Constraints

- Board files only under `docs/pipeline/`; each starts with `...@classes`, then `direction: down`; no board imports another; `class:` is a node's first attribute.
- Only the nine classes of `classes.d2`. No new shapes, no styles.
- A note is a child of the node it annotates, label `|md ... |`. A `gap` note is a single-line `|md Gap: ... |`; its directives trail the closing `| {class: gap}` on the same line.
- English; domain words exactly as in `CONTEXT.md`. Never write "local currency", "trading currency", "reported currency", "functional currency"; "quality gate(s)" is spelled exactly that (lower case, one space; a capital Q only at the start of a sentence).
- Formulas in plain math with Unicode operators (`×`, `÷`, `−`, `≥`, `≤`), never function names.
- Every acronym is a key of `_ACRONYMS` or `_ACRONYMS_EXEMPT` with its expansion earlier in the board or on the same line. On `site.d2` write "a YYYY-MM-DD date", not "ISO date"; "uv" in lower case.
- Directives live in `#` comments trailing the line whose visible text they check, never inside `|md ... |`. A `@const`/`@param` value must be visible on that same source line (a multi-line label stays one source line with `\n`). Tuples: every element shown on that line.
- **Numbers on `step` labels** (new rule, pinned by `test_every_step_has_purpose_and_edges`): every number written in digits on a step's declaration line equals the value of a `@const` or `@param` directive on that line, except 0, 1, 100 (the percent scale), ordinals (`3.` followed by a space), and digits inside words or form names (`10-K`, `5-year`, `t−1`). Structural counts are written in words ("at least two years").
- **ADR mentions** (pinned by `test_adr_mentions_carry_their_status`): every `ADR NNNN` (or `(ADR) NNNN` at first use) on a board is followed by its status in parentheses, exactly as the ADR's status text writes it: `ADR 0006 (Implemented)`, `ADR 0005 (Not implemented)`, `ADR 0001 (Accepted)`.
- **Document gaps** (pinned by `test_document_gaps_are_current`): a gap raised against the plans or the lesson names the document as `plano <card>` (a card key of `docs/plano/part-data.js`) or `leccion cap-N`, and quotes or paraphrases the claim.
- Every edge carries a label. Edges are declared at top level, after all nodes, with dotted paths.
- Do not touch `src/`. Never hand-write or edit an SVG or `rendered.sha256`.
- `docs/pipeline/README.md` at most 60 lines.
- Quality bar: `uv run ruff check . && uv run mypy src && uv run pytest -q` green, and the `pipeline-diagram` workflow green on the head commit.
- Commits: board work `docs(#144): ...` (story convention); pipeline stages `test(#150)`, `fix(#150)`, `chore(#150)`.

## Review Focus

1. **A gap that stopped being true.** Each document gap is tied to a phrase that must still be in the document (`_DOC_GAPS`), so fixing `part-data.js` or `index.html` fails the suite until the note goes.
2. **A verdict computed two ways.** The list row's verdict is the sidecar's verdict text; the value line and grid cells recompute `verdict_of(MoS)`. The board says both; `test_site_verdict_sources_match_code` reads `row_view` / `scenario_grid` source.
3. **A workflow step reordered or added in `site.yml`.** `test_site_ci_steps_match_workflow` compares the numbered `ci.*` labels with the `run:` / `uses:` lines of the workflow, in order.
4. **An unsafe output directory.** The `build.out_dir` decision states the three refusals of `_prepare_out_dir`; `test_site_text` pins them.
5. **A d2 syntax error only CI sees.** Copy syntax only from boards that render (`portfolio.d2`, `analyze.d2`); the controller reads `gh run view <id> --log-failed`.
