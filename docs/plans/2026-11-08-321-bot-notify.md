# bot notify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `.agents/skills/subagent-driven-development/SKILL.md` to implement this plan task-by-task; implementers write code with `.agents/skills/test-driven-development/SKILL.md`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `bot notify` command that sends the text on its stdin, verbatim, through the notifier configured by `BOT_NOTIFIER`, so a shell script can report a failed run.

**Architecture:** One new Typer command in `src/bot/cli.py`, built only from what already exists: `load_settings()`, `build_notifier(settings)` and `Notifier.send(text)`. It reads `sys.stdin`, never opens the database and never takes a lock. Its error mapping mirrors `bot portfolio` (misconfigured → 2, send failure → 1). The README `### Notifications` section gets one paragraph, pinned by a docs test.

**Tech Stack:** Python 3, Typer 0.25 / Click 8.4 (`CliRunner` keeps `result.stdout` and `result.stderr` apart), pytest, mypy --strict, ruff.

**Spec:** GitHub issue #321 (nicolas-ricc/damodaran), "feat(#118): bot notify sends the text on stdin through the configured notifier". The story context and design decisions are in the plan comment on parent #118.

## Global Constraints

- Command name `notify`, visible in `bot --help` (not `hidden`). There is no `--text` option. The message is `sys.stdin.read()`.
- Messages and exit codes, verbatim:
  - `BOT_NOTIFIER=none`: stdout `No notifier configured (BOT_NOTIFIER=none), nothing sent`, exit 0.
  - `NotifierConfigError`: stderr `Notifier misconfigured (BOT_NOTIFIER=<channel>): <exc>`, exit 2.
  - Empty or whitespace-only stdin with a notifier configured: stderr `Nothing to send: the message on stdin is empty`, exit 2.
  - `NotificationError`: stderr `Message not sent: <exc>`, exit 1.
  - Success: stdout `Sent via <channel>`, exit 0.
- The text is sent exactly as read: no header, no strip, no added newline.
- The command does not call `_open_db`, `connect`, `apply_schema` or anything else from `bot.storage`, takes no lock, and does not read or check the Flex settings.
- Tests monkeypatch `bot.cli.build_notifier`, following the existing pattern in `tests/unit/test_cli_portfolio.py` (`_RecordingNotifier`). They set `BOT_SEC_USER_AGENT` with `monkeypatch.setenv`, because `load_settings()` requires it.
- `uv run ruff check . && uv run mypy src && uv run pytest -q` green. Commits use Conventional Commits scoped `(#321)`.

## Review Focus

1. **Non-ASCII text** (`€`, `✓`, accented letters from a log tail) has to reach `send` unchanged. This is pinned in Task 1 by `test_notify_sends_stdin_verbatim`.
2. **Leading blank lines and a trailing newline** have to be kept. The email backend picks the subject itself, so the CLI must not strip anything. Pinned by the same test, whose input starts with `\n` and ends with `\n`.
3. **Misconfigured channel and empty stdin together**: the config error wins (exit 2, `Notifier misconfigured`), because the channel is checked before stdin is read. Pinned by `test_notify_misconfigured_wins_over_empty_stdin`.
4. **`BOT_NOTIFIER=none` with empty stdin**: exit 0 with the nothing-sent line, never `Nothing to send`. Pinned by `test_notify_without_notifier_sends_nothing` running with `input=""`.
5. **No Flex settings and a DB path that does not exist**: the command still succeeds and leaves no DB file. Pinned by `test_notify_never_opens_the_database`, which blanks `BOT_IBKR_FLEX_TOKEN` and `BOT_IBKR_FLEX_QUERY_ID`.

### Task 1: `bot notify` command

**Files:**
- Modify: `src/bot/cli.py`: add `import sys`, and add the `notify` command right after `portfolio` (before `flex_capture`).
- Test: `tests/unit/test_cli_notify.py` (new)

**Interfaces:**
- Consumes: `bot.cli.build_notifier(settings: Settings) -> Notifier | None` (tests monkeypatch it), `NotifierConfigError`, `NotificationError` and `load_settings()`. All of them are already imported in `cli.py`.
- Produces: the CLI command `notify` (Python function `notify() -> None`). Sibling issue #322 calls it as `... | uv run bot notify`.

- [ ] **Step 1: Write the failing tests** in `tests/unit/test_cli_notify.py`

Shared helper `_env(tmp_path, monkeypatch) -> Path`: it sets `BOT_SEC_USER_AGENT="Test test@example.com"`, sets `BOT_DB_PATH=tmp_path/"bot.duckdb"`, and returns that path. A `_RecordingNotifier` class has `sent: list[str]` and `send(text)`, which appends.

Every test invokes `CliRunner().invoke(app, ["notify"], input=...)`.

- `test_notify_sends_stdin_verbatim`: monkeypatch `bot.cli.build_notifier` to `lambda settings: rec`, and set `BOT_NOTIFIER=telegram` so `<channel>` is known. Use `text = "\n# daily.sh failed: portfolio (exit 1)\n\nlog tail — € ✓ café\n"`. Assert `exit_code == 0`, `rec.sent == [text]` and `"Sent via telegram" in result.stdout`.
- `test_notify_without_notifier_sends_nothing`: set `BOT_NOTIFIER=none` and do not monkeypatch; use `input=""`. Assert `exit_code == 0` and that `result.stdout` contains `No notifier configured (BOT_NOTIFIER=none), nothing sent`.
- `test_notify_misconfigured_exits_2`: set `BOT_NOTIFIER=email`. Monkeypatch `build_notifier` to raise `NotifierConfigError("missing BOT_SMTP_HOST")`. Use `input="# hello\n"`. Assert `exit_code == 2` and `"Notifier misconfigured (BOT_NOTIFIER=email): missing BOT_SMTP_HOST" in result.stderr`.
- `test_notify_misconfigured_wins_over_empty_stdin`: the same setup with `input=""`. Assert `exit_code == 2`, `"Notifier misconfigured" in result.stderr` and `"Nothing to send" not in result.output`.
- `test_notify_empty_stdin_exits_2` is parametrized over `["", "\n", "  \n\t"]`. Use a recorder notifier. Assert `exit_code == 2`, `"Nothing to send: the message on stdin is empty" in result.stderr` and `rec.sent == []`.
- `test_notify_send_failure_exits_1`: set `BOT_NOTIFIER=telegram`. The notifier's `send` raises `NotificationError("Telegram sendMessage HTTP 400: chat not found")`. Assert `exit_code == 1` and `"Message not sent: Telegram sendMessage HTTP 400: chat not found" in result.stderr`.
- `test_notify_never_opens_the_database`: use the recorder, and set `BOT_IBKR_FLEX_TOKEN=""` and `BOT_IBKR_FLEX_QUERY_ID=""`. Assert `exit_code == 0` and `not db_path.exists()`.
- `test_notify_is_listed_in_help`: `invoke(app, ["--help"])` has `"notify"` in its stdout, and `invoke(app, ["notify", "--help"])` exits 0.

- [ ] **Step 2: Run the tests and confirm they fail**

Run: `uv run pytest -q tests/unit/test_cli_notify.py`
Expected: FAIL. Typer reports `No such command 'notify'` (exit 2), so the exit-code and output assertions fail.

- [ ] **Step 3: Implement `notify() -> None` in `src/bot/cli.py`**

The order is fixed by Review Focus 3: `load_settings()`, then `build_notifier` (map `NotifierConfigError` to exit 2), then the `None` branch (print the nothing-sent line and return without reading stdin), then `sys.stdin.read()`, then the blank check, then `send`, then the success line. The docstring is the `--help` text: one summary line ("Send the text on stdin through the configured notifier."), plus the exit codes and a note that it never opens the database.

Expected: all pass, no lint or type errors.
