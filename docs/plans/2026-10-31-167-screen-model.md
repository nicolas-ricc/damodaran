# Screen model (TLA+, TLC-checked) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A checked TLA+ model of `bot screen`: one company from its snapshot through the coverage gate, the three rule layers and the two-pass ranking to its persisted row, with thirteen rules as INVARIANTs.

**Architecture:** Three files beside the site model in `docs/pipeline/models/`: `screen.tla` (one company, one run; `phase` is the reader's state; one named action per thing that happens), `screen.cfg` (`SPECIFICATION Spec` + one `INVARIANT` per rule), `screen.view.js` (labels, groups = the six screen sub-boards). The convention tests in `tests/unit/test_pipeline_models.py` already run over every `*.tla`; one screen-specific test is added. TLC runs in CI only (job `models` of `pipeline-diagram`).

**Tech Stack:** TLA+ (TLC 1.7.4), the statechart skill at `STATECHART_COMMIT`, ES module view, pytest.

**Spec:** GitHub issue #167 (parent story #161, design decisions 6, 7, 9 in its plan comment). Model conventions: `docs/pipeline/models/README.md`; worked example: `docs/pipeline/models/site.tla`, `site.cfg`, `site.view.js`.

## Global Constraints

- Files: `docs/pipeline/models/screen.tla`, `screen.cfg`, `screen.view.js`; first line `---- MODULE screen ----`.
- Groups are exactly `screen-snapshot`, `screen-coverage`, `screen-quality`, `screen-value`, `screen-traps`, `screen-ranking`.
- `Next == A1 \/ ... \/ Done`; `Done == phase \in EndPhases /\ UNCHANGED vars`; `Spec == Init /\ [][Next]_vars`; deadlock checking stays on.
- Each rule: a `\*` reader's sentence on the line(s) directly above its definition, preceded by a `(* Cites: ... *)` comment naming the code it mirrors. `\*` is reserved for rule sentences; every other comment is `(* ... *)`. Each action carries a `(* ... *)` citation of the code it mirrors.
- View maps `states`, `steps`, `groups` are plain `const` (not exported: the skill's view loader rejects other exports, see the #163 plan's Assumptions), one `key: "value",` per line, keys unquoted. The five exports verbatim as in `site.view.js`; `title = "screen: one company through bot screen"`.
- Labels: reader's words, no underscore, no camelCase, no action name; acronyms expanded at first use; conditions in `[brackets]` at the end of a step label.
- About 20 arrows per group (hard cap 24), counting steps with source or target in the group plus the stores/services the sub-board will attach.
- At most a few hundred distinct states (chart budget 500).
- No file under `src/` or `docs/pipeline/*.d2` changes. Pipeline code never changes in this task.
- TLC cannot run in the sandbox (no Java, downloaded binaries refused); CI is the gate.

## Review Focus

- A rule that holds only because the model cannot express its violation (a tautology). Each rule below names the variable whose other value would break it; the reviewer checks that some action could, in principle, set that value.
- A company without `industry_damodaran` but whose provider industry has a benchmark row with a WACC: the code looks the benchmark up first (`run_screen` calls `load_industry_benchmarks` before the gate) and still rejects as `industry_unmapped`. The model must allow `bench = "with_wacc"` with `mapped = FALSE`.
- A company rejected only because all four value indicators were skipped: persisted with `passed = false` and no failed value rule (`evaluate_company`: `elif not result.skipped`). Rule (m) pins it.
- A survivor cut by `--top`: in no `screener_candidates` row at all (`persist_candidates` writes `result.shortlist` and `result.rejected` only; cut survivors are in neither). Rule (h) pins it.
- A state-space blow-up from storing values the reader does not need (region, tax rate): those steps change only `phase`.

#### The rules (thirteen INVARIANTs, in this order in `.tla` and `.cfg`)

| name | formula | reader's sentence |
| --- | --- | --- |
| (a) `UnmappedLeavesAsUnmapped` | `~mapped => (layersRun = {} /\ reasons \subseteq {"industry_unmapped"})` | A company without a Damodaran industry never reaches a rule and leaves as industry_unmapped, whatever its sector benchmark. |
| (b) `NoWaccNoRule` | `bench # "with_wacc" => layersRun = {}` | A company without a sector benchmark weighted average cost of capital (WACC) never reaches a rule. |
| (c) `UncoveredCurrencyNoRule` | `currency = "uncovered" => (layersRun = {} /\ ((reasons # {} /\ mapped /\ bench = "with_wacc") => reasons = {"currency_uncovered"}))` | A company whose reporting currency is uncovered never reaches a rule, and leaves as currency_uncovered when no earlier reason applies. |
| (d) `OneCoverageReason` | `("rejected_by_coverage" \in outcomes <=> reasons # {}) /\ Cardinality(reasons) <= 1` | A company rejected by the coverage gate has exactly one reason. |
| (e) `EveryLayerRecorded` | `"traps" \in layersRun => (layersRun = Layers /\ (qualityFailed => "quality" \in recorded) /\ (valueOutcome = "failed" => "value" \in recorded) /\ (trapsOutcome \in {"failed", "skipped"} => "traps" \in recorded))` | Every layer runs on a measured company, even after a failed gate, so the failed rules of every layer are recorded. |
| (f) `FailedLayerRejects` | `(qualityFailed \/ valueOutcome \in {"failed", "skipped"} \/ trapsOutcome \in {"failed", "skipped"}) => (~inPercentiles /\ ~kept /\ row # "passed")` | A failed quality gate, no passing value indicator, or a failed or skipped trap detector rejects the company, and it is never ranked. |
| (g) `OnlySurvivorsInPercentiles` | `inPercentiles => (layersRun = Layers /\ ~qualityFailed /\ valueOutcome = "passed" /\ trapsOutcome = "passed")` | Only a company that passed all three layers enters the percentiles. |
| (h) `CutNeitherValuedNorSaved` | `(dcf # "not_run" => (kept /\ inPercentiles)) /\ (phase = "cut" => (dcf = "not_run" /\ row = "none" /\ ~reported))` | The second pass values only survivors kept on the shortlist, and a survivor cut by the top N is neither valued nor saved. |
| (i) `UnvaluedKeepsPlaceholder` | `(dcf = "failed" => margin = "placeholder") /\ ((kept /\ phase \in EndPhases) => (row = "passed" /\ reported))` | A kept survivor that cannot be valued keeps the placeholder margin of safety, and is still saved and reported. |
| (j) `RejectedSavedAsFailed` | `((outcomes \cap {"rejected_by_coverage", "rejected_by_rules"} # {} /\ phase \in EndPhases) => row = "failed") /\ (row = "failed" => ~reported)` | A rejected company is saved with passed set to false, and is not in the report. |
| (k) `OneEndOnly` | `Cardinality(outcomes) <= 1` | A company reaches at most one end: rejected by the coverage gate, rejected by the rules, cut, or saved on the shortlist. |
| (l) `NoUsdCapFailsQuality` | `(capInUsd = "none" /\ "quality" \in layersRun) => qualityFailed` | A company whose market cap has no value in US dollars (USD) fails the quality gates. |
| (m) `SkippedValueRecordsNothing` | `valueOutcome = "skipped" => "value" \notin recorded` | When every value indicator is skipped, the company is rejected with no failed value rule recorded. |

## Assumptions

- Rule (a) is reworded: the issue's "before the benchmark is looked at" cannot be cited, because `run_screen` calls `load_industry_benchmarks` (with the provider industry as fallback) before the gate checks `industry_damodaran`. The citable rule: the reason is `industry_unmapped` whatever the benchmark lookup found. The issue allows the replacement; the PR says so. Rejected alternative: treating it as a broken rule, which would file a "bug" for a lookup whose result is ignored.
- Rule (c) carries the precedence ("when no earlier reason applies"): `CoverageReason` precedence puts `currency_uncovered` last. Rejected alternative: the literal wording, which TLC would break on an unmapped company with an uncovered currency, reporting the documented precedence as a bug.
- Four rules beyond the issue's eleven: (l) no USD market cap fails the quality gates (`MinMarketCap`), (m) an all-skipped value layer records no failed value rule (`evaluate_company`), both stated on `screen.d2`; they give the sub-boards two sentences for the criteria the reader most often gets wrong.
- The trap skip (`ATrapDetectorIsSkipped`) is guarded by `bench # "with_wacc"` and so never fires after the gate: the only skipping detector is `roic_above_sector_wacc`, and only without a sector WACC. It stays in the model so (e)/(f) state the ADR 0006 rule; the chart does not draw it (TLC never takes it).
- The valuation currency is read in the snapshot group (`currency_read`), though the gate is where it decides: the code reads it in bulk before the loop (`_load_reporting_currencies`), and a variable set before the gate is what keeps rule (c) from being a tautology.
- Region and tax steps change only `phase`: no rule reads them, and storing them would multiply the states.
- The view maps are plain `const`, as in the site model and the models README, not `export const` as the issue's text writes: the skill's loader rejects other exports.
