# daily.sh and weekly.sh wait for the shared DB lock — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `scripts/daily.sh` and `scripts/weekly.sh` run every `uv run bot ...` command while holding the advisory lock `$REPO/.cache/bot.lock`. Each one waits up to `BOT_DB_LOCK_WAIT` seconds (default 900) for the lock and fails with exit 75 and a logged `lock timeout:` line when the wait runs out.

**Architecture:** Each script gets the same small `locked` bash function, which wraps `flock -w "$LOCK_WAIT" -E "$LOCK_BUSY" "$LOCK" "$@"`. It is defined after `LOG=` and the sync re-exec, and every `uv run bot ...` call goes through it. The lock is taken per command, so it is released during `daily.sh`'s pause between rounds and while `publish_site.sh` runs. Exit 75 goes into the existing failure flow unchanged. The tests live in `tests/integration/test_scripts.py` and use its harness. They hold the lock from the test process with `fcntl.flock`.

**Tech Stack:** bash, `flock(1)` from util-linux 2.39, pytest, shellcheck (`.venv/bin/shellcheck`).

**Spec:** GitHub issue #311 (`gh issue view 311 --repo nicolas-ricc/damodaran`). Its parent story is #108, and the planner comment there holds the shared design. The issue's "Design decisions (inherited, do not reopen)" section is binding, and the `locked` function body is exact copy taken from it.

## Global Constraints

- Lock file `"$REPO/.cache/bot.lock"`. The scripts never delete it. `flock` is called by name, with no fallback when it is missing.
- `LOCK_WAIT="${BOT_DB_LOCK_WAIT:-900}"`. A value that does not match `^[0-9]+$` falls back to `900`. `LOCK_BUSY=75`.
- The timeout line is exactly `lock timeout: $LOCK still held after ${LOCK_WAIT}s, skipped: $*`, written once per timed-out command.
- Do not touch `scripts/price_fill.sh`, `.env.example`, `install_cron.sh`, or the README Quickstart paragraph. The sibling child #310 owns `price_fill.sh` and the Quickstart.
- Every existing test in `tests/integration/test_scripts.py` stays green and unchanged. All scripts stay executable and shellcheck-clean.
- `uv run ruff check . && uv run mypy src && uv run pytest -q` green.

## Assumptions (declared)

- The pause-release test (3) and the publish-without-lock test pass on the unlocked scripts too, because nothing holds the lock there. They guard against regressions: they fail if a later change holds the lock across `sleep` or `publish_site.sh`. Every other new test fails before the change.
- The fake `flock` in test 5 records `flock <argv>` lines in `calls`. Only that test sees them.
- Task 1's commit leaves the weekly params of the parametrised tests red until Task 2 lands, just as the evals commit leaves every new test red. The branch is green from Task 2 on, and only the PR head has to be green. Rejected alternative: `xfail` markers that Task 2 removes again.
- Worst-case wait (grilling Q7): a timed-out price round stops the rounds, so `daily.sh` waits at most two timeouts (prices, FX). Portfolio is skipped because the worst code is not 0. `weekly.sh` waits at most one, because the `&&` chain stops. When each command gets the lock after a wait, the waits add up. That follows from the per-command granularity, which the issue makes binding.
- A missing `flock` gives exit 127 to the same failure flow. It is not tested, because the issue says "No fallback when missing".
- The README criterion is pinned by one new test in `tests/integration/test_scripts.py`. It reads the `## Scheduling` section and checks for the facts the criterion lists, not for exact wording.

## Review Focus

1. `publish_site.sh` must run without the lock. If it held the lock, a future `bot` call inside it would deadlock. Pinned by `test_weekly_runs_publish_site_without_the_db_lock` (Task 2).
2. A timed-out daily price round must still let FX try. With the lock held, FX times out as well, so the run exits 75 with two timeout lines and no `uv` calls. Pinned by test 1 for daily: exit 75 and an empty `_calls`.
3. Under `set -uo pipefail`, the function must not leak a `local status` problem or swallow the exit code. Existing exit-code tests (`FAKE_*_EXIT` 1–5) must still pass through `flock` unchanged. Pinned by the existing tests.
4. In `daily.sh` the timeout line must reach the log through `$out`, because the capture swallows stdout. Pinned by test 1 for daily (the log contains `lock timeout:`).
5. `BOT_DB_LOCK_WAIT="soon"` must not make `flock` fail with a usage error (exit 64) before it tries. Pinned by test 5.
